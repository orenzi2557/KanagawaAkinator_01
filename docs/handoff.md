## 0. 3 行でいうと

1. 観光地データは **`data/spots.json`（100 件）**、説明文は **`data/descriptions.json`**、質問は **`data/questions.json`** の 3 つの JSON に入っています。
2. 「質問に答えるとスポットを提案する」計算は **`lib/engine/`**（React に依存しない純粋な JavaScript）にまとまっていて、そのまま別のアプリに持っていけます。
3. 統合したら **`npm run validate:data`** と **`npm test`** で、データとロジックが壊れていないかを確認できます。

## 1. アプリの全体像

質問（最大 12 問）に答えると、神奈川県内の観光地 100 件の中から合うものを選び、結果画面に次のものを表示します。

- 1 位のスポット（マッチ度 %、マッチ理由のタグ、基本説明、AI の「あなたに合う理由」）
- 地図と、1 位の近くのスポット 2 件（距離 km つき）
- **おすすめエリア**: 1 位と同じエリアの、好みに合うスポット 3 件
- 2 位・3 位の候補（クリックで 1 位と入れ替え）

```
画面（app/）
  │  回答
  ▼
状態管理（lib/state/quizReducer.js）
  │
  ▼
エンジン（lib/engine/）  ← data/spots.json, data/questions.json を読む
  ├ score.js           スコア計算
  ├ selectQuestion.js  次の質問を選ぶ
  ├ finish.js          終了判定
  ├ nearby.js          近くのスポット
  └ area.js            おすすめエリア
  │
  ▼
結果の組み立て（lib/result.js）→ 結果画面（app/result/page.js）

自由記述 → /api/parse-text → Ollama（ローカル LLM）。失敗したらキーワード辞書（lib/llm/keywords.js）
結果画面 → /api/explain   → Ollama で「あなたに合う理由」。失敗したらテンプレート文
フィードバック → /api/feedback → SQLite（data/app.db）
```

技術: Next.js 16（App Router）/ React 19 / JavaScript のみ（TypeScript なし）/ Tailwind CSS 4 / Leaflet（地図）/ better-sqlite3 / zod / Vitest。
LLM（Ollama）は**なくても動きます**（質問から提案までは LLM を使いません）。

### 3.2 `data/questions.json`（質問、27 問）

2 種類あります。

```json
{ "id": "r_budget", "tier": "required", "text": "予算はどれくらい？",
  "options": [ { "label": "なるべくお金をかけずに", "budget": 1, "effect": {} }, ... ] }

{ "id": "q_flower", "tier": "deep", "text": "季節の花や庭園を楽しみたい？", "tag": "flower" }
```

- `required`（必須質問、3 問）: 最初に定義順に出す。選択肢ごとに `effect`（タグ → 加点）と、予算の質問だけ `budget` を持つ
- `deep`（踏み込んだ質問、24 問 = 12 タグ × 2 問）: 共通の 4 択（はい +2 / たぶんそう +1 / どちらでもない 0 / いいえ −2）で答え、`tag` を 1 つ持つ

## 4. 提案ロジックの仕様（`lib/engine/`）

### 4.1 回答（answer）の形

```js
{
  questionId: "q_flower",
  choice: "yes",          // deep は "yes" | "probably" | "neutral" | "no"、required は options の添字（0〜）
  text: "",               // 自由記述（空でよい）
  textScores: null,       // 自由記述の解析結果 { tag: -2〜2 }（なければ null）
  textBudget: null,       // 自由記述から読み取った予算 1〜3（なければ null）
}
```

### 4.2 スコア

```
score(spot) = Σ deep 回答の重み × spot.tags[質問のタグ]
            + Σ 必須回答の effect[tag] × spot.tags[tag]
            + Σ 自由記述の点数[tag] × spot.tags[tag] × TEXT_WEIGHT
            − BUDGET_PENALTY × max(0, spot.budget − 利用者の予算)
```

同点のときは `spots.json` で先に書かれたスポットが上になります。マッチ度 % は全スポットのスコアを min-max 正規化した値です。

### 4.3 次の質問・終了・近く・おすすめエリア

- **次の質問**: 必須質問を定義順に 3 問 → その後は、スコア上位 `TOP_K` 件のスポットで、そのタグの値の分散が最大の deep 質問（自由記述で強く表明済みのタグ・聞き済みのタグは優先度を下げる）
- **終了**: deep を `MIN_DEEP_QUESTIONS` 問以上聞き、1 位と 2 位の差が `LEAD_THRESHOLD` 以上になったら終了。または合計 `MAX_QUESTIONS` 問で終了
- **近くのスポット**: ハバーサイン距離で 1 位に近い順に `NEARBY_COUNT` 件
- **おすすめエリア**: 1 位と同じ `region` のスポットを、スコアの高い順に `AREA_SPOT_COUNT` 件（1 位・近くのスポット・2 位・3 位は除く）

### 4.4 定数（`lib/engine/constants.js`、調整はこのファイルだけで行う）

| 定数                          | 値   | 意味                                                      |
| ----------------------------- | ---- | --------------------------------------------------------- |
| `TEXT_WEIGHT`                 | 1.0  | 自由記述の点数にかける重み                                |
| `BUDGET_PENALTY`              | 3    | 予算オーバー 1 段階あたりの減点                           |
| `TOP_K`                       | 10   | 次の質問を選ぶときに見る上位スポット数（18 件のときは 6） |
| `STRONG_TEXT_THRESHOLD`       | 2    | 自由記述で強く表明されたとみなす累積点数                  |
| `STRONG_TEXT_VARIANCE_FACTOR` | 0.25 | 強く表明済みタグの質問の優先度にかける係数                |
| `ASKED_TAG_VARIANCE_FACTOR`   | 0.5  | 聞き済みタグの質問の優先度にかける係数                    |
| `MIN_DEEP_QUESTIONS`          | 4    | 終了判定: deep 質問の最低問数                             |
| `LEAD_THRESHOLD`              | 4    | 終了判定: 1 位と 2 位のスコア差                           |
| `MAX_QUESTIONS`               | 12   | 合計問数の上限（18 件のときは 10）                        |
| `NEARBY_COUNT`                | 2    | 近くのスポットの件数                                      |
| `AREA_SPOT_COUNT`             | 3    | おすすめエリアに並べる件数                                |
| `MAX_REASON_TAGS`             | 3    | マッチ理由タグの最大数                                    |
| `SPOTS_PER_GENRE`             | 10   | データ検証: ジャンルごとの件数                            |

## 5. 統合のしかた

### パターン A: 観光地データだけを使う（いちばん簡単）
